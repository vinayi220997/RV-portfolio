8. ADMIN ACCESS CODE SYSTEM

Implement the following user experience.

Footer entry field

Add a discreet field in the public website footer.

Field placeholder/label: #code

Hint text: #role

Expected behavior:

Accept codes beginning with #.
Trim accidental surrounding whitespace.
Validate format and length.
Show the message Code not existed for an unrecognized code.
Route an accepted access identifier to the appropriate admin login screen.
Reserved default access identifier

The reserved identifier is: #admin

Requirements:

It must always remain reserved.
It cannot be deleted through the admin panel.
It cannot be renamed through the admin panel.
It cannot be disabled by deleting or modifying a normal custom-code record.
It must not automatically bypass authentication.
It must not grant administrative access by itself.

IMPORTANT SECURITY RULE:

The frontend is public. Any code embedded in frontend JavaScript, HTML, JSON, or a public repository can be discovered. Therefore, #admin must be treated as an access identifier or route selector, not as a secret password.

Perform actual authorization on the trusted backend. Never grant access merely because the browser submitted #admin.

Custom admin codes

Allow an authorized administrator to:

Add multiple custom access codes beginning with #.
Assign a descriptive role or label.
View their status.
Rename or rotate custom codes if supported by the chosen authorization model.
Delete custom codes.
Disable and re-enable custom codes.
Review creation and modification dates.
See validation errors for duplicate or malformed codes.

The reserved #admin identifier must remain protected.

Custom codes should be high-entropy random tokens if they function as bearer credentials. Do not treat predictable role names or short strings as secure authentication secrets.

Store sensitive code verifiers securely on the backend. Do not expose a list of active secrets in public files or client-side code.
